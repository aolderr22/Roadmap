STEP 1 — Azure Resources

Created resource group `rg-healthcare-ai`.

Created Azure Storage Account `sthealthcaredocs2026` using Azure Blob Storage / Data Lake Storage Gen2.

Region: East US.

The storage account will serve as the persistent document storage layer for the healthcare RAG project.
---
STEP 2 — Healthcare Document Storage

Created the `healthcare-documents` container in Azure Storage Account `sthealthcaredocs2026`.

Configured the container for private access.

Uploaded one healthcare PDF document to the container.

The documents are now stored in Azure Blob Storage / Data Lake Storage Gen2 and ready to be connected to the RAG retrieval pipeline.
---
STEP 3 — Azure AI Search

Created Azure AI Search service `search-healthcare-ai`.

Resource group: `rg-healthcare-ai`.

Region: Central US.

Pricing tier: Basic.

Central US was used because East US was unavailable for creating a new Azure AI Search service.

Azure AI Search will provide the retrieval layer for the healthcare RAG pipeline.
---
STEP 4 — Microsoft Foundry

Created Microsoft Foundry resource `foundry-healthcare-ai`.

Created Microsoft Foundry project `proj-healthcare-ai`.

Region: East US.

The Foundry project will provide the model and agent infrastructure for the healthcare RAG system.
---
STEP 5 — Embedding Model

Deployed the `text-embedding-3-small` embedding model in Microsoft Foundry.

The deployment is available to the Foundry project and will be used to generate vector embeddings for documents ingested by Azure AI Search.

The project is using the New Foundry experience.
---
STEP 6 — Generation Model

Deployed the `gpt-5-mini` model in Microsoft Foundry.

Deployment name: `gpt-5-mini`.

The model will provide the generation/reasoning layer for the healthcare RAG agent.

The project uses the current New Foundry experience. `gpt-5-mini` was selected instead of the previously considered `gpt-4.1-mini` to avoid building the project around an older model lifecycle.
---
STEP 7 UPDATE — Foundry Project Search Access

Enabled the system-assigned managed identity for the Microsoft Foundry project `proj-healthcare-ai`.

Granted the `Search Index Data Reader` role on Azure AI Search service `search-healthcare-ai` to the managed identity of the Foundry project.

This permission allows the Foundry Agent Service to securely access the Azure AI Search knowledge base through the knowledge base MCP endpoint.
---
STEP 8 — Azure AI Search Blob Knowledge Source

Created Blob Knowledge Source `ks-healthcare-docs` in Azure AI Search.

The knowledge source connects Azure AI Search to the `healthcare-documents` container in storage account `sthealthcaredocs2026`.

Text vectorization is enabled using the embedding model deployed in Microsoft Foundry.

The healthcare PDF has been ingested into the Azure AI Search retrieval pipeline.

Azure AI Search automatically created the indexing pipeline required to make the document available for agentic retrieval.
---
STEP 9 — Azure AI Search Knowledge Base

Created knowledge base `kb-healthcare` in Azure AI Search.

Connected the knowledge base to the Blob Knowledge Source `ks-healthcare-docs`.

Configured `gpt-5-mini` as the model deployment for the knowledge base.

The knowledge base now provides the agentic retrieval layer for the healthcare RAG system, orchestrating retrieval from the healthcare document knowledge source and supporting grounded answer generation.
---
STEP 10 — Foundry RAG Agent

Created the Microsoft Foundry prompt agent `agent-healthcare-rag` using the deployed `gpt-5-mini` model.

Connected the agent to the Azure AI Search knowledge base `kb-healthcare`.

The knowledge base provides grounded retrieval from the healthcare document stored in Azure Blob Storage through the `ks-healthcare-docs` knowledge source.

Tested the agent successfully with a question based on the healthcare document and verified that the response is grounded in the source with citations.
---
